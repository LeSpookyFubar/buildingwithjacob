Ground Station Zero

Investigate two fictional ground station cases and write a finding you can explain. The full educational kit adds four cases, an 18-page workbook, source tests and an optional NASA EONET provenance exercise.

This is a synthetic learning exercise, not a live ground station or orbital simulator. No NASA affiliation or endorsement. The HMAC key is public and can be used by anyone to forge matching signatures. No real AI model is called or evaluated.

Start here

  1. Extract the entire sample ZIP and open index.html in a current browser. If local files are restricted, run python3 -m http.server 8000 --bind 127.0.0.1 in the extracted folder and open http://127.0.0.1:8000.
  2. Select a mission, read its brief and click Analyze evidence. Follow finding links into source rows; click a row number for all fields.
  3. Write what you observed, a possible non-adversarial cause, and the evidence you would seek next.
  4. Export Markdown and CSV. Case backup saves the current case and notes as JSON; use Import case and rerun analysis to restore it. Keep one backup per case. Browser saving is optional.

01 · Establish the baseline

Six nominal records describe two invented ground stations, GS-ALPHA and GS-BRAVO. Compare sequence numbers within each station, not across the whole table. The fixed snapshot reference is 12:02:00 UTC on June 1, 2026.

  1. List each station’s sequence numbers in arrival order.
  2. Calculate the age of its latest telemetry from the fixed reference time.
  3. Compare signal against −100 dBm and battery against 20%. Equality does not cross these strict thresholds.
  4. Explain what zero configured-rule findings can and cannot establish.
Baseline answer key — open after writing your notes

Expected result: 0 findings. GS-ALPHA has 100,101,102; GS-BRAVO has 200,201,202. Latest observations are 12:01:00 and 12:01:10, ages 60 and 50 seconds. Neither exceeds the 300-second freshness threshold. All six signatures match their teaching key and the provided measurements are above alert thresholds.

This does not prove a real system is secure. The case contains only selected fields and rules. The key is public; a knowledgeable sender can make a matching signature for invented or altered data.

02 · The duplicate in the stream

A signed arrival is repeated, a sequence is missing, and a later arrival contains an older timestamp. Keep arrival order intact while distinguishing these conditions.

  1. Run the checks and independently verify each flagged row.
  2. Convert a zero-based evidence index to its displayed row by adding one. Source index3 is displayed row4.
  3. Explain why a valid HMAC can coexist with replay, missing records or delayed delivery.
  4. Write a short conclusion with one alternative cause and a concrete follow-up.

Make a report worth reading

Use this structure in Analyst notes:

  1. Scope: this named synthetic dataset and fixed reference time.
  2. Observation: exact station, displayed row and source index.
  3. Interpretation: which rule condition is satisfied.
  4. Counter-evidence: another explanation the records do not rule out.
  5. Next step: evidence that could distinguish those explanations.
  6. Limits: public teaching key, fictional measurements, selected fields and rules.

The app makes no network requests. Notes stay in memory unless you explicitly enable saving or export a backup. The sample and full edition keep separate browser-save namespaces. Keep source datasets and backups with your exported findings.
